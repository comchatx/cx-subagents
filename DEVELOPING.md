# Developing cx-subagents

Install it in your own pi with `pi install npm:@comchatx/cx-subagents`.

## How it is built

- **Two extensions for cx, `extensions/board-cards.ts` and `extensions/hand-out.ts`, and two for a helper alone, `extensions/steps.ts` and `extensions/own-folder.ts`.** pi loads them as TypeScript; there is no build. It ships no skill. When cx hands work to the background is cx's own judgement with pi-subagents' `subagent` tool. `hand-out.ts` keeps one sentence beside that tool's guidelines on whose call it is: cx gets it once in each request, and a fresh helper none. A helper started with `context: "fork"` carries cx's conversation, and the sentence with it, because that is what a fork is. Whether a helper may hand work on is pi-subagents' own setting, which `agents/helper.md` leaves as pi-subagents sets it.
- **What it listens to.** pi-subagents emits `subagent:async-started` and `subagent:async-complete` on the session's event bus. The start carries the run id, the `subagent` call's id and the run's folder, and redacts the task. The extension takes the task from pi's own `tool_call` event for that call. The end carries the result's state and its duration.
- **The tab.** `comchatx.board` declares the board tab 帮手 / Helpers and its page, `page/helpers.html`. The page draws from the tab's files through the board's `cxBoard` and writes only a card's `title` line, when the seller renames a helper. It draws each face with cx's figure as the board hands every page, `window.CxCharacter`, in the pair's two colours, and carries no figure of its own; on a board that hands none, a face's place is left empty and the card stands as it is. The one colour the board's theme values lack, the outline of what ended with no result, the page carries itself.
- **The card.** It goes in `board/<person>/帮手/` under the session's directory, which in cx's computer is `/tenant`. The person is the one the session names in `CX_PERSON_FACTS`, else the one directory under `board/`; a board with none, or with more than one and no person named, gets no card. The extension imports nothing from `cx-board` and calls nothing of the board's.
  - The name is `<YYYYMMDD-HHMMSS>-subagent-<run id>.md`, the start's time in UTC.
  - The front matter holds one JSON value a line: `kind: "helper"`, `title`, `face`, `state`, `at`, then `ended`, `took`, `ran`, `since`, `run`, `dir`, `files` and `reads` where they are known. `ran` is the seconds the helper worked before its present stretch at work and `since` when that stretch began, so the time a card shows runs only at work and stands while the helper waits or is paused. The title is the task's first line, at most 200 characters; `face` is one more than the highest in the tab. The words are the task as given, cut where the whole file would pass the 32 KiB the board reads.
  - Each write puts the whole file beside its name and renames it over the name.
- **A helper's own folder.** `agents/helper.md` loads `extensions/own-folder.ts` in a helper alone (`subagentOnlyExtensions`). pi-subagents hands every child its task as the first prompt of its session (`Task: …`), however cx started it: one task, a parallel workflow, a scripted chain, or a `chain` or `tasks` that pi-subagents compiles where workflow scripts are off. pi's `input` event lets the extension add to that prompt. Where the session holds no user message yet, it makes `帮手/<person>/<YYYYMMDD-HHMMSS>/` in cx's folder, `-2` and on for a second helper in the same second, and adds one sentence after the task: the folder is its own, a place the task names wins, and data bought with `cx get` stays where it lands (`ownFolder`). The person is read as the card's is. The helper still starts in cx's folder, where the seller's plugins are declared (`<tree>/.pi/settings.json`), so it loads them; started in the folder itself it would load none. A continuation (`resume`) is told nothing more: its session already holds the first prompt, and with it the folder. cx's call and the card's task stay as cx asked them.
- **What cx is told of going on** (`GO_ON`, beside the tool's guidelines): more of the same work goes on with the helper that did it, with `resume`; within minutes of its last step that is cheap, later it reads its whole earlier run again; unrelated work starts a new helper (Jack, 2026-11-17).
- **What cx is told of a fork** (`FORK`, beside the tool's guidelines): a helper started with `context: "fork"` carries cx's conversation and is told no folder of its own. A fact, no rule: nothing in the package asks cx to fork, and pi-subagents starts a helper `fresh` by default.
- **What a card lists.** `files` holds what the helper wrote and `reads` what it read, first first, each once. They come from the run's `events.jsonl`: a `tool_execution_start` line of `write`, `edit`, `read` or `fetch_content` gives the call's `path`, `url` or `urls`, and its `tool_execution_end` line, joined by `toolCallId`, when `isError` is not true, adds them; the card is rewritten when that adds an entry that fits, and not otherwise. One decoder reads the whole log, so a name cut by the edge of a read is read whole. A file is named by its path in the session's directory, the folder the board opens a file from, a relative path read against it; one outside that folder is left out, since the board cannot show it, and of what it read, a file under a folder whose name begins with a dot is left out too: that is pi's and the packages' own, a skill's `SKILL.md` and its references under `.pi/npm`, a session's files, and none of it is the seller's. A page is its `http` or `https` address. At the run's end the log is read once more before the card's last write, and a run that finished puts first among the files the report pi-subagents keeps for it, its result's `savedOutputPath` or else its `artifactPath` (`<session dir>/subagent-artifacts/<run>_<agent>_output.md`, in the tree since the box keeps its sessions under `.pi/sessions`); a run paused, stopped or cut short adds none. pi-subagents deletes those reports after `artifactConfig.cleanupDays`, seven by default, and the card's box then opens no file. A call's `output` is not used to put the report elsewhere: pi-subagents rewrites the helper's task with that path as the one that wins, over a place the task names. Where the log stopped at its 50 MiB bound (its `subagent.events.truncated` line), the four tools' calls that ended well are taken from the helper's session file, each step's `sessionFile` in the result. The two lists stop growing at 24 KiB together, about three hundred long addresses, the earliest kept.
- **On the page** a card holds up to three files as the board's file box, past three two of them and 查看全部 {count} 个文件, and {count} 份参考资料 where it read anything. Either press puts that helper's whole list in the cards' place, the files, then what it read, pages before files; ← 帮手 or Escape goes back to the cards, the keyboard on the press it came by and that press in view. The board scrolls outside the page's frame and grows the frame back to the cards' height after the page draws them, so the page brings the press into view as it draws them, by the browser's own `scrollIntoView`, which moves the board's scroll from inside the frame; where the page's height changed with that draw, once more at the frame's next resize, the board's, and where it did not, no resize comes and nothing waits for one. An arrival keeps the keyboard on the same file or page in the same part of the list. A file's box is the board's own (`data-cx-file`): the board shows the file on a tab of its own. A page opens in a new tab of the browser.
- **The states.** A card starts `working`. While the run waits on a blocking supervisor call (`contact_supervisor` asking for a decision or an interview, or `intercom` asking), read from the run's `events.jsonl` as pi-subagents appends it, the card is `waiting`, and `working` again at that call's end. A pause counts as a wait does: the present stretch is added to `ran` and `since` goes. At the end it becomes `done`, `failed`, `timeout`, `stopped` or `paused`, with `ended`, `took` as the run reports its duration, the wall's, and `ran` counted the same way; the page shows `ran` only for a card at work, a paused one among them, and `took` in a done card's line; the name and face the file holds are kept, so a rename stands.
- **At each session's start** the extension moves its own earlier cards into `帮手/`, from every place one can lie: the person's `todo/` and `done/`, where 0.3.5 and the versions before it wrote them, and the `todo/` and `done/` of each tab of the board, where the board's own move of those two places into its module's tab took them, whichever of the two moves ran first. A card is the package's when its name is a start's time, `-subagent-` and the run, and its head is what those versions wrote: `kind: finding`, the title as one JSON string and the start in ISO 8601 UTC, with no other line but the `done`, `doneAt` and `answer` the module adds to one the seller handled; any other file stays where it is, untouched. Handled cards move too, as finished: each comes as `done` (`timeout` where its words start 超时), ended at its file's last write. Where `帮手/` already holds a file of that name, whatever it holds, nothing is written and nothing removed: the earlier card stays where it is. The person's own `todo/` and `done/` are removed when that leaves them empty; a tab's places stay as the board made them. Then each card still at work whose run a stop of cx's computer cut becomes `off`, and the rest are followed again. A run was cut where its folder holds no `status.json`, as when the folder was in `/tmp`, or where its `status.json` still reads `running` or `queued` under a `bootId` that is not this boot's (`/proc/sys/kernel/random/boot_id`), as when the folder is on the disk. Such a run's end, `failed` by pi-subagents' own reconciliation, leaves its card `off`.
- **Where pi-subagents keeps its runs.** `comchatx.env` asks the computer to set `PI_SUBAGENTS_TEMP_ROOT` to `{data}/pi-subagents`, a folder on its disk kept across a stop and never synced, at pi's start, before pi-subagents loads; the package cannot set it itself, since pi loads pi-subagents first and its runner would then read another folder than it. pi-subagents makes the folder and clears its ended runs after 30 days, 90 while the run can be continued. On a computer that does not set it, or has no such place, the runs stay in `/tmp` and go at a stop.
- **The presses.** A working card offers 暂停 / Pause, a paused one 继续 / Resume, and each at work 停止 / Stop, asked once before it is done since a stopped helper cannot be continued; one no longer at work offers 移除 / Remove. The page writes the press into the card's front matter, and nowhere under it, as `press: "pause"`, `"resume"`, `"stop"` or `"remove"` and draws the card at once as the press leaves it. The extension watches the tab, and for each card with a press does it by pi-subagents' own control on the session's bus (`subagents:rpc:v1:request`): `interrupt` for a pause, `resume` with "Go on with your task from where you paused." for a resume, `stop` for a stop; a remove deletes the file of a card no longer at work. The card is then written again without the press, as the run stands. A press that does not fit the state the card's file says, or that pi-subagents refuses, is taken out of the file, and the rest of the card stays as the file reads.
- **A message to a helper.** A card working, paused, done or failed offers 给帮手发消息 / Message, which opens the board's own message box (`cxBoard.box`) on the card. Its words go to cx in the chat as `**@name** words`, with the card attached (`cxBoard.send`), and where the board answers `sent` the card says 已交给 cx / Sent to cx; where it answers `drafted`, the words are in the chat's own box, the card's box closes, and the card says nothing. `hand-out.ts` keeps two more sentences beside the `subagent` tool's guidelines: cx passes such words on with `subagent`, `steer` while the helper works and `resume` once it has paused or ended, and leaves a helper the seller paused or stopped as it is; and `GO_ON` above. A resume keeps the helper's card: the start pi-subagents emits for it, which carries no tool call id, is taken as that card's while exactly one resume is out, so the card is `working` again on the new run, its `ran` kept. In each request the extension adds one line where cx reads a helper's question, naming the helper's card, and one to a message written on a card, naming that card's run. The card is the one the board's own mark at the message's end names (`<board from="帮手" card="…">`), not the name in its words, so two cards of one name each reach their own helper; a `**@name**` message typed in the chat gets no line.
- **A helper's steps.** A helper lists its own steps with rpiv-todo's `todo` tool (`@juicesharp/rpiv-todo`, MIT), which npm installs with this package. `agents/helper.md` loads it in a helper alone, by `subagentOnlyExtensions: ../extensions/steps.ts, ../extensions/own-folder.ts`; that file only hands on rpiv-todo's own extension, so node finds it wherever npm put it, nested under this package or beside it, and pi does not load it for cx, which has no such tool. Each `todo` result carries the whole list in its `details`; at that call's `tool_execution_end` in `events.jsonl`, when `isError` is not true and the result holds a list with no `error`, the card's `steps` become that list: a completed step `done`, the one in progress `now`, a pending one `todo`, a deleted or empty one left out, each step's first line at most 200 characters. The card keeps them through each write and at its end, and through a resume, paused, done or failed alike, until its next `todo` call that ends well; that call's list is the one rpiv-todo keeps in the helper's session, its earlier steps and its new ones. The page draws them under the card's head and the question before a stop, before what the helper wrote, as the signed sheet draws them: a step in work is drawn 已暂停 / Paused while the helper is paused or waits for cx, and 未完成 / Not finished once its card ended.
- **pi-subagents' config is carried by the box,** not this package. `asyncByDefault` sends a run to the background. `toolActivation: "eager"` offers the `subagent` tool from the first request. `maxActiveAsyncRunsPerSession: 2` caps the runs in one conversation at two; a third is refused, not queued, so no card is written as queued. The 30 minutes is pi-subagents' own default for a background run.

## Facts

- Finished cards accumulate in `帮手/`; nothing removes them. A helper's folder stays too, after its card is removed; the seller asks cx to remove it.
- The folder holds what a helper makes only as far as the model follows the sentence: a file it writes elsewhere is still in cx's folder, and listed on the card where a tool wrote it.
- A call cx starts with no person's board to write to gets no folder and no sentence, as it gets no card.
- A child of another of pi-subagents' agents (`worker`, `scout` and the rest) gets a card and is told no folder: the sentence is loaded by this package's `helper` alone. Its files land where it writes them and show on its card.
- A helper started with `context: "fork"` carries cx's conversation, so its first prompt is not its session's first user message: it gets a card and is told no folder, and cx is told so (`FORK`). Its files land where it writes them and show on its card.
- The board's icon carries no mark while a helper runs.
- The sand ink is 2.75:1 on a light card.
- A card lists what a helper wrote and read with the four tools only: a file a command writes, a page a command fetches and data bought with `cx get` are not on it.
- A file or page that arrives redraws the page, and the board keeps no place for the seller: what stands below a new row moves down by that row, on a card by up to 37 px a time and on the list page by 33 px a file. The keyboard stays on the control it was on; a file box that gives its place to 查看全部 hands the keyboard to that press.
- A helper cx starts with a working directory of its own (`subagent`'s `cwd`) has a relative path read against the session's directory, so its box may show a file of that name there, or none.
- A path whose first part in cx's folder begins with two dots, such as `..notes/a.md`, is not listed: it reads as one outside that folder.
- A file's box on the page has one mark, as the board draws a box in a page's words; the board's own mark under the pointer or the keyboard is the chat's box, not a page's.
- Two helpers ending together each write their own file, by run id and by rename, so nothing is lost; the board shows both within one look.
- A computer stopped under a run cuts it: at the next start the card is marked `off`. A run whose folder still holds `status.json` is followed again and keeps its state.
- A rename and the package's own write of the same card at one moment can each win, either way: the seller's name over a newer state, or the state over the name; the next write or rename sets it right.
- A run that ended while the package was not there to hear its end stays 正在处理 until a new start reuses the card.
- With more than one person's board on the computer and nobody named, no card is written, and the tab says nothing more than its empty line.
- A start cut between the write and the removal of an earlier card leaves the earlier copy in its old place beside the new card in `帮手/`, and it stays there.
- A seller's own file in a tab's `todo/` or `done/` that carries both a card's name and the head those versions wrote would be moved to `帮手/` as finished; none is known.
- The time is counted from when the package hears an event, so a wait heard late is counted late.
- No state line is written to any log.
- What pi-subagents' own clearing leaves in its folder on the disk (a run that never ended, its leases and its channels) stays until the computer's volume goes; nothing of the computer's sweeps it.
- A run cut by a stop on a system that gives no boot id is not marked `off` while its folder stands.
- A pause wakes cx for one turn: pi-subagents tells cx the background task paused.
- A press acts on the run the card's file names in its `run` line, and Remove deletes any file in `帮手/` whose name ends as a card's and whose state is not at work. The package alone writes those files, so a press goes astray only where a hand changed a card's `run`, put a note of another kind in the tab under a card's name, or left a card reading done while its run goes on. The file's own name cannot stand in for its `run`: a resumed card keeps its name while its run changes.
- The message box's control reads 交给 cx / Send to cx, the names in both languages the page gives the board's box once, the board drawing the one for its language; a board whose box does not yet take a name shows the chat's 发送 / Send, and nothing else changes.
- A card has one message box: words typed in it stay there when the board's language changes, and words sent are gone from it.
- A press and the package's own write of the same card at one moment can lose the press; the card then stands as the run does, and the seller can press again.
- Two resumes cx starts at once each make a card of their own.
- A stopped helper cannot be continued: pi-subagents refuses to resume it.
- A paused end heard with no card in the tab shows the wall's time.
- Where both the cards and one list pass the frame's 100,000 px cap, the way back takes no second look.
- A card's steps stop at 6 KiB, which holds 26 steps of 200 Latin letters or 9 of 200 Chinese characters, and more shorter ones: the first are kept and those after them are not shown.
- rpiv-todo adds its own guidance for the `todo` tool, about 323 words, to each helper's requests, and none to cx's.
- A `todo` call rpiv-todo refuses changes nothing on the card.
- A helper that ends with a step still in progress shows that step 未完成 / Not finished, on a done card too.
- Steps arrive as the log is read: a card can show a step list a few seconds old until the next `todo` call or the run's end.

## Release

`.github/workflows/release.yml` publishes each version on a `v<version>` tag, once this repository is the package's trusted publisher on npm. Until then a maintainer publishes by hand, `npm publish --access public` from a checkout of the merged tag.
